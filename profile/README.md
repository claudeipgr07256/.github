<p>评测住宅 IP 最怕的不是测不准，而是变量没控住：今天换线路、明天换账号、后天换请求脚本，最后谁也说不清差异来自哪。这篇用对照实验的思路，把纯净度、延迟、并发三件事拆成可以并排比较的组：同一账号、同一时段、同一套请求脚本，只改出口这一个变量。文末给一张能直接套用的评测表，以及两周一次的复测节奏，适合手上已经有两三家候选、需要拍板选一家的人。</p>

<h2>一、先把实验条件钉死</h2>
<p>三组对照跑下来，最容易出问题的不是数据，而是中途有人顺手改了浏览器插件或者切了 Wi-Fi。所以开测之前先把条件写下来贴在群里：账号固定、设备固定、时段固定、请求脚本固定，唯一变化的是出口地址。</p>
<h3>账号要同源</h3>
<p>拿一个新注册的空号和拿一个用了半年的号去测，结果没有可比性，因为新号本身处在敏感期。理想情况是同一批同一天注册的账号，分别挂不同出口，跑同样的动作。</p>
<h3>时段要覆盖两个窗口</h3>
<p>至少覆盖工作日下午两点到五点、晚间八点到十一点这两个窗口。只看白天数据，晚高峰的抖动会被完全掩盖，而晚高峰恰恰是最容易暴露线路问题的时段。</p>

<h2>二、纯净度对照：三个查询入口交叉验证</h2>
<p>单一入口的结论经常互相打架，同一个地址在 A 站显示住宅、在 B 站显示机房，这很常见。做法是三个入口都查一遍，看是否一致，再看谁能解释不一致的原因。</p>

<h3>注册主体与网段要一起看</h3>
<p>用 whois 或 RDAP 查注册主体，能看出这个网段是运营商直接分配，还是被层层转租。转租层级越多，邻居地址被滥用的概率越高，你的地址被牵连的机会也越大。这一步不花钱，只是花时间。</p>
<h3>ASN 与 company type 字段</h3>
<p>ipinfo 这类服务会给出 ASN 和 company type，住宅宽带通常落在 ISP 类别，托管商落在 hosting。注意这个字段是推断值，不是权威结论，所以要和反向解析、路由跳数一起看。</p>
<h3>黑名单与历史记录</h3>
<p>查黑名单建议用两三个不同的库，结论不一致时以"多数命中"为准。历史滥用记录一般查不到公开数据，只能向供应商索要，或者用地址在前几个月的可用性做间接判断。</p>

<h2>三、延迟对照：ping 只是第一层</h2>
<p>很多人拿 ping 的毫秒数当唯一指标，这个数只反映 ICMP 往返，和实际打开页面的体感差得远。真正影响体验的是三段：DNS 解析、TLS 握手、首字节返回。三段里任何一段抖，用户就会觉得"卡"。</p>
<h3>把三段耗时分开记</h3>
<p>用 curl 的 -w 参数可以一次输出 dns、connect、tls、ttfb 四个时间，例如 curl -w "%{time_namelookup} %{time_connect} %{time_appconnect} %{time_starttransfer}\n" -o /dev/null -s 目标地址。每家跑三十次，取中位数，比单次 ping 有说服力。</p>
<h3>晚高峰必须单独复测</h3>
<p>白天 40ms、晚上 180ms 的线路并不少见，原因是跨境出口在高峰期拥塞。把晚间八点到十一点的数据单独列一列，和白天对比，差距超过一倍就要在选型时打个问号。</p>

<h2>四、并发对照：5、20、50 线程下的成功率</h2>
<p>并发测试的意义在于找出拐点：什么时候开始出现明显失败。做法很简单，同一段请求脚本，分别用 5、20、50 个线程各跑十分钟，记录成功数、失败类型和响应时间分布。</p>
<h3>把失败类型分开统计</h3>
<p>429 是限流、超时是线路、5xx 是服务端，这三类混在一起看会得出错误结论。线路差通常表现为超时占比上升，而 429 变多往往说明请求节奏太快，和出口质量关系不大。</p>
<h3>看 P95 而不是平均值</h3>
<p>平均值会被大量快速成功的请求拉低，P95 才能反映那 5% 的糟糕体验。四十个请求里有两个卡到三秒，平均值可能只涨了一点点，但用户感受到的就是这两次。</p>

<h2>五、把四组数据写成一张评测表</h2>
<p>数据散在几个终端里没有意义，最后要落到一张表：每家一行，纯净度、延迟、并发、稳定性四列，每列给一个可以解释的结论，而不是只写数字。写结论的过程，往往就是发现某一列其实没测够的过程。</p>
<h3>用同一套阈值判定</h3>
<p>阈值要提前定，不能等数据出来再调。比如纯净度要求三个入口中至少两个显示住宅、黑名单零命中；延迟要求晚高峰 P95 不超过 600ms；并发要求 20 线程下成功率 95% 以上。</p>
<h3>两周复测一次</h3>
<p>线路质量会随时间变化，尤其是共享池。刚开通时干净，不代表一个月后还干净。建议固定每两周复测一次纯净度和晚高峰延迟，把结果记在同一张表里，趋势比单点更有价值。</p>

<h2>常见问答</h2>
<h3>没有专业工具能测纯净度吗？</h3>
<p>答：可以，浏览器打开两三个 IP 查询站，比对 ASN、company type、是否命中黑名单三项即可。缺点是拿不到历史数据，也看不到邻居地址的情况，适合做初筛而不是终审。</p>
<h3>延迟低就一定好用吗？</h3>
<p>答：不一定。延迟低但抖动大的线路，体感往往比延迟稍高但稳定的线路差。看 P95 和标准差，比看平均值靠谱。跨境线路尤其如此，白天和晚间的差距可能超过一倍。</p>
<h3>并发测试会不会把账号跑出问题？</h3>
<p>答：会，如果用真实账号跑高并发。建议用测试账号或只读接口做压力测试，真实账号保持日常节奏。把测试流量和业务流量分开，是评测阶段的基本原则。</p>
<h3>复测发现数据变差要马上换供应商吗？</h3>
<p>答：先排查自身变化。设备、网络、脚本、账号状态都可能影响结果。排除自身因素后，如果连续两轮都变差，再考虑换线，避免因为一次异常就仓促迁移。</p>

<h2>合规提示</h2>
<p>本文所述评测方法用于自有账号的网络质量评估与故障排查，不涉及对第三方平台的规则规避。请勿使用压力测试手段对目标服务发起超出正常使用范围的请求。</p>
<p>选购与使用代理服务时，应确认服务商资质合法、用途与业务一致，并按所在地法规与平台条款留存必要的记录。</p>
